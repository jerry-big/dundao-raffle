断刀·锻刀大会

一把断刀，三人成器。参与者自选刀身、刀柄、护手，然后一锤一锤自己敲，敲到系统说停为止—— 次数越高，品质越好，分数越高；分数越高，刀越豪华。全场按分数排名，一等奖 1 名、二等奖 3 名、三等奖 25 名。

终端 手机 H5 / 微信内打开 玩法 逐锤锻打 参与 每人一次（openid） 发奖 群内截图 + 编号核验 风格 像素复古

01这是什么东西，解决什么

先定义产品，再谈细节。这一节只回答三个问题：给谁用、怎么玩、玩完得到什么。

用户与场景

一场约 50–200 人的线下/社群活动，参与者用微信扫码进入，在手机上单独完成一局，几十秒内结束。

核心动作

选三个配件 → 一锤一锤自己敲 → 看见锻打次数、品质和分数 → 保存一张结果卡。

完成标志

玩家拿到带唯一编号的结果卡；运营在后台看到一条完整记录，活动结束后可一键排出 29 个获奖名额。

一句话产品定义

「断刀」是一个用锻刀小游戏包装的排名制抽奖活动页：玩家一锤一锤亲手敲出仪式感， 但敲打次数在你入炉那一刻就已由服务端随机定死，点击只负责爽感；名次与奖品在活动结束后由后台统一结算，玩家之间以结果卡截图在群内核验领奖。

为什么这样设计

  • 逐锤锻打：每一下都要玩家自己点，锤数、火花、分数一起涨，爽感来自手感和反馈；但次数在入炉时就由服务端定死，敲得快慢不影响结果，所有人胜率一致。
  • 配件定轮廓，分数定华贵：三个配件决定刀的基本造型，不影响数值；最终分数越高，材质、刃纹、护手装饰和光效越豪华，既避免"选错配件就输了"，又让高分有炫耀价值。
  • 排名制：奖品集中在少数名次上，悬念强、话题性强；代价是需要一个明确的截榜时间和同分规则，见 06 共享规则。
  • 结果卡截图：不开发领奖系统，把发奖成本压到最低，用"唯一编号 + 后台记录"兜住核验。

核心公式

锻打次数 N
入炉瞬间由服务端在 12 – 24 之间按权重定死，对玩家保密，点击不会改变
单锤得分
固定 4,000 分，N 锤累加——分数天生就是五位数，越看越像锻出了神兵
品质加成
按 N 落入的品质额外加一笔：0 / 500 / 1,000 / 1,500 / 2,000 / 3,000 / 4,000
余烬 E
服务端随机 0 – 9，最后一锤迸出的火星，只做同分段内的尾数
总分 S
S = N × 4,000 + 品质加成 + E，取值 48,000 – 100,009，满分 10 万
排名
S 降序 → S 相同比完成时间（早者优先）→ 再相同比编号（小者优先）

余烬只有 0–9 分，永远不可能让 12 锤反超 13 锤（相邻两档差 4,000 分）， 所以"次数越多分越高"是硬规则；它只负责在同次数、同品质的两个人之间分出先后。 24 锤神品刚好打到 100,000，这个数字本身就是结果页的最大彩蛋。

敲打交互规则

  • 一锤一点：每点一次「落锤」只落 1 锤，分数 +4,000，同时触发锤击动画、屏幕震动和火星。
  • 次数保密：N 在入炉时就定好，玩家不知道要敲几下，敲到第 N 锤才自动成刀——爽感和悬念都在这一下一下里。
  • 手感递进：锤数越多，火花越密、震动越强、刀身从暗灰烧到橙红，敲到二十锤以后明显上头。
  • 不拼手速：没有倒计时，也没有连点倍率，点得快只会更快结束，不会改变结果。
  • 可中断：中途退出、切后台、断网都保留已敲锤数，回来接着敲，进度不清零。
  • 不可提前收刀：必须敲满 N 锤才能成刀，未成刀不产生分数与排名。

05功能需求

按模块拆分，每条都写清触发条件、处理规则、结果与异常。P0 是本次上线必须做的，P1 是可选增强。

FR-01 入口与微信授权 P0

项目说明
触发用户用微信扫描活动二维码，或在群内打开活动链接
处理静默网页授权获取 openid；首次授权失败或用户拒绝时，展示说明页，提供「重新授权」按钮
规则openid 是唯一身份。一人只能有一条有效锻刀记录，与设备、微信号更换无关

若公众号未开通网页授权权限，需在上线前确认资质；这是本项目唯一的外部前置依赖。

FR-02 活动首页与状态拦截 P0

  • 首页内容：活动名、活动时间、玩法三句话、奖项与名额、当前参与人数（可选）、“开始锻刀”按钮。
  • 状态拦截：未开始 → 倒计时页，按钮置灰；进行中 → 正常进入；已结束 → 结束页，只能查看自己的结果与规则。
  • 规则页：独立页面，说明次数区间、品质、排名与同分规则、发奖方式。它同时是活动合规要求的落点。

FR-03 配件选择（纯外观） P0

项目说明
结构三步选项卡：刀身 → 刀柄 → 护手，每步 4 个外观选项，已选步骤打勾
预览顶部实时渲染当前组合的刀；切换选项立即变化，不做加载动画
默认值每类默认选中第 1 个，允许一路「下一步」直接开始
规则配件只决定刀的轮廓，不影响次数、品质与分数；成刀后的材质、刃纹、装饰、光效由品质（即分数）决定
状态未选满三类不可进入锻打台；返回上一步保留已选内容
异常中途退出：若未入炉，回到配件选择并恢复上次选择；若已入炉未成刀，回到锻打台接着敲；已成刀则按 FR-06 处理

FR-04 逐锤锻打与结果生成 P0

项目说明
触发玩家进入锻打台，点击「落锤」，且活动进行中、本人无有效记录
处理① 入炉时服务端按权重抽定 N（12–24）并对玩家保密 → ② 每次点击上报锤序号，服务端校验递增并累加 4,000 分 → ③ 第 N 锤触发成刀：判定品质、计算品质加成与余烬 → ④ 生成唯一编号并落库
幂等锤序号必须连续；同一锤重复上报只返回当前进度，不重复加分；N 一旦生成不可修改
反馈每锤都有锤击动画、屏幕震动、火星和「+4,000」飘字，锤数越多效果越强；成刀时按品质播放 1.5–3 秒的淬火定格动画
结果写入锻刀记录（配件、次数、余烬、品质加成、分数、品质、编号、入炉时间、成刀时间），玩家进入结果页
异常断网：本地暂存锤数，恢复后按序补报；连点：节流合并但一锤不漏；中途退出：保留进度，回锻打台继续敲

FR-05 结果页与结果卡 P0

  • 结果页：品质大字、次数与余烬、总分、三件配件、编号，以及按分数呈现的刀身外观；下方提示「名次将在活动结束后公布」。
  • 结果卡：可直接长按保存的图片，内容包含活动名、日期、品质、锻打次数、余烬、总分、编号、玩家昵称（可打码）。不显示名次，因为此时尚未锁榜。
  • 禁止重玩：结果页不提供"再来一次"，这是规则的一部分，不是交互省略。
  • 二次进入：已参与者再次打开，直接呈现结果卡与「查看规则」，不出现锻打入口。

FR-06 重复参与拦截 P0

判定依据是 openid 是否已存在已完成（已敲满 N 锤成刀）的锻刀记录。命中时：直接展示该记录的结果页，任何按钮都无法开启新一局；文案为「你已经锻过一把刀」。

同一个人换手机、换微信号 → 视为不同参与者（openid 不同），这是规则允许的边界，不做额外设备指纹校验。

FR-07 排名、锁榜与结算 P0

项目说明
排名全部有效记录按总分降序；同分比完成时间（早者优先）；再同分比编号
锁榜活动结束时间一到，自动锁定可参与状态；已生成的记录全部有效
结算运营在后台点「结算」，系统生成 1 / 3 / 25 名获奖名单并固定，界面进入「已公布」
重算结算后如需作废某条记录（作弊、测试数据），须走「作废 + 重算」，并留存操作日志
展示玩家在活动结束后打开结果页，可看到自己的名次与奖项；未进榜显示「未入榜」

FR-08 群内核验与发奖登记 P0

这是本方案替代"核销系统"的环节，规则必须写死，否则会出现冒领和重复领。

  1. 活动结束、后台结算后，运营在群内公布获奖名单（名次 + 编号后四位 + 昵称首字），不公布完整编号。
  2. 获奖者把结果卡截图发到群里，运营用编号在后台查询记录。
  3. 后台查询结果需展示：是否存在、是否在获奖名单内、名次、奖项、完成时间、openid 尾号。
  4. 核对无误后，运营在后台标记「已发放」，同一条记录不能重复标记；标记后名单显示已发放状态。
  5. 编号查不到、截图与后台记录不一致、或该编号已被标记发放 → 拒绝并说明原因。
防伪逻辑：结果卡上没有名次，玩家无法用 P 图伪造"一等奖"；最终以后台榜单为准， 群内截图只是"认领凭证"。这才是把发奖交给群聊还能控住风险的前提。

  • 公开实时榜（会显著改变玩家策略与心理，需单独评估）。
  • 结果卡附二维码，扫码进入查询页，进一步降低核验成本。
  • 参与奖：未进前 29 名也可凭结果卡领取小纪念品。
  • 分享海报：结果卡增加"再锻一把"式的邀请文案（注意：被邀请者仍受一人一次限制）。

06共享规则（唯一定义）

这些规则被多个模块引用，只在这里定义一次，功能章节只引用不重复。

R1 计分与排名

总分 = 锻打次数 × 4,000 + 品质加成 + 余烬，锻打次数 12–24，品质加成 0–4,000，余烬 0–9，满分 100,009。

排序：总分降序 → 完成时间升序 → 编号升序。三条比较键保证名次唯一，不存在并列。
其中"完成时间"指第 N 锤落下的服务端时间，不是进入页面或入炉的时间。

R2 时间与锁榜

时点系统行为
活动开始前只读首页与规则，锻打按钮不可用
进行中可入炉、可逐锤锻打、可查看本人结果
结束瞬间已入炉但未成刀的可继续敲完，成刀时间以第 N 锤为准；此后的新入炉一律拒绝
结算后名次固定，结果页显示奖项；后台可作废并重算

R3 编号规则

格式 DD-XXXX-XXXX：前段 4 位大写字母数字，后段 4 位数字，全局唯一、不可顺序推测。编号在一次锻刀落库时生成，此后不变，是群内核验的唯一凭据。

R4 概率与控奖边界

概率只能以"档位权重"的方式整体配置，不支持按人、按微信号指定结果。理由是：一旦可以内定，截图核验就失去意义，且对参与者构成明显不公。

合规提示（非法律意见）：若活动面向不特定公众、以奖品吸引参与，通常需要在规则页公示活动时间、奖品名称与数量、参与方式与限制。 本方案已把规则页列为 P0；正式对外前建议确认活动主体与当地要求。

R5 数据留存

锻刀记录、发放标记、后台配置变更均保留至活动结束后 [TBD：建议不少于 30 天]，用于申诉与对账；openid 不对外展示完整值，后台仅显示尾号。

07状态与异常

边界情况写清楚，开发和运营才不会各自猜。下表是上线前必须逐条确认能跑通的清单。

场景系统处理玩家看到
非微信浏览器打开不渲染游戏，拦截到引导页「请在微信中打开」+ 二维码
拒绝微信授权不写记录，允许重试「未授权无法参与」+ 重新授权
活动未开始禁止入炉与锻打倒计时
活动已结束禁止新开局，可查结果结束页 + 我的结果入口
选完配件未入炉就退出保留"选配中"记录，恢复选择回到配件页，选择还在
入炉后未敲完退出 / 切后台保留已敲锤数，不清零回到锻打台，接着敲
敲到一半断网本地暂存锤序，恢复后按序补报「正在接续炉火…」
连续快速点击节流合并，但一锤不漏、不重复加分分数连续上涨
活动结束时仍在敲允许敲完，成刀时间以第 N 锤为准正常出结果
某一锤请求超时重试同一锤序号，服务端幂等不丢锤、不重复计分
已参与再次进入不再开局「你已经锻过一把刀」+ 结果卡
后台结算时 0 人参与生成空名单并提示无（运营侧）
获奖者编号查不到拒绝发放运营告知「记录不存在」
同一条记录重复领奖第二次标记被拒绝，显示首次发放时间运营告知「已发放」
结算后需要改结果作废 + 重算，全程留痕名次可能变化，需公告说明

08运营动线与发奖流程

这套方案把"发奖"放在了群聊里，所以运营动作必须提前排练一遍。

活动前
  1. 后台创建活动，设置起止时间
  2. 核对概率权重与名额（1 / 3 / 25）
  3. 生成二维码，群内预热 + 线下物料张贴
  4. 用测试微信号跑 3–5 局，确认幂等与重复拦截
活动中
  1. 盯后台实时看参与量与异常（同一 openid 多记录、报错率）
  2. 群内播报当前第一名分数，制造悬念
  3. 不做人工干预结果
结束后 10 分钟内
  1. 后台一键结算，导出获奖名单
  2. 群内公布名次 + 编号后四位 + 昵称首字
  3. 说明领奖截止时间与地点
发奖
  1. 收截图 → 后台查编号 → 核对名次
  2. 发放并标记「已发放」
  3. 对拒绝案例留存截图与说明

#待定项为什么需要你定建议
1活动起止时间与锁榜时点排名制必须有一个明确的截止时刻，否则无法结算现场活动定在结束前 10 分钟截榜
2预计参与人数直接决定 1/3/25 的名额比例是否合理，以及概率权重按 80–150 人配置
3各等奖具体奖品规则页与群内公告需要写清奖品名称和数量一等 1 份、二等 3 份、三等 25 份
4是否设参与奖决定未进前 29 名的人是否有兜底，影响现场情绪建议设小额纪念品
5次数区间与概率权重决定整体分数分布与一等奖分数段先用 03 节默认值
6结果卡是否显示昵称、是否打码涉及隐私与群内认领的可识别性显示昵称首字 + 完整编号
